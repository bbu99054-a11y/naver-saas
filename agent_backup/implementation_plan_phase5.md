# Phase 5: 전문직(YMYL) 맞춤형 안전성 및 프롬프트 고도화 플랜

대표님께서 받아오신 타 LLM의 진단 결과는 2026년 현재 전문직(법률, 세무 등 YMYL) 타겟 SaaS가 반드시 갖춰야 할 핵심 페인 포인트들을 정확히 짚어냈습니다. 

특히 6개의 프롬프트 모듈이 하나로 합쳐지며 발생하는 **'지시문 망각(Lost in the Middle)' 현상**과 **'광고법 위반 리스크'**는 즉각적인 해결이 필요합니다. 이를 바탕으로 우리 SaaS에 100% 즉시 적용 가능한 **실현 가능한 기능 4가지**를 선별하여 기획안을 도출했습니다.

---

## 🎯 도입 확정 기능 (적용 가능성 100%)

### 1. XML 태그 기반 프롬프트 리팩토링 (망각 방지 엔진)
현재는 문자열을 단순히 이어 붙이는(Single-prompt) 방식입니다. 이를 최신 2026년 프롬프트 엔지니어링 표준인 **XML 캡슐화** 방식으로 전면 개편합니다.
- `<system_constraints>`, `<expert_persona>`, `<compliance>` 등으로 프롬프트를 명확히 구획하여 LLM이 중간 지시사항을 무시하거나 잊어버리는 현상을 원천 차단합니다.

### 2. 전문직 광고법 컴플라이언스 린터 (Compliance Filter)
변호사법, 세무사법 등에서 징계 대상이 되는 **금지어(과장 광고)**를 AI가 원천적으로 사용하지 못하도록 강제합니다.
- **적용:** 프롬프트 내에 특별 네거티브 룰 추가 ("무조건 승소", "100% 절세", "국내 최고" 등의 단어 절대 사용 금지)

### 3. 법적 면책 조항(Disclaimer) 자동 삽입
전문직 블로그의 필수 요소인 법적 면책 조항을 CTA 풋터 하단에 자동으로 덧붙입니다.
- **적용 문구:** *"본 포스팅은 일반적인 정보 제공을 목적으로 하며, 구체적인 사안에 따라 법적 판단이 달라질 수 있으므로 반드시 정식 상담을 받아보시기 바랍니다."*

### 4. HTML 정화기(Sanitizer) 룰셋 강화
스트리밍 특성상 백엔드에서 실시간 코드를 뜯어고치기는 까다로우므로, 프롬프트의 `<html_constraints>` 태그 내에 스마트에디터 ONE에서 깨지는 CSS 속성(`display: flex`, `grid`, `position: absolute` 등)을 절대 사용하지 못하도록 강력한 화이트리스트 규칙을 주입합니다.

## ⚠️ 보류 또는 차후 도입 기능 (User Review Required)
> [!WARNING]
> 다른 LLM이 제안한 아래 기능들은 현재 단계에서 적용하기에 **가성비(ROI)가 떨어지거나 인프라 확장이 필요하여 일시 보류**를 제안합니다. 동의하시는지 확인 부탁드립니다.
> 
> 1. **2단계 생성 파이프라인 (JSON 뼈대 -> HTML 렌더링)**: 적용 시 글이 나오기 시작하는 시간(TTFB)이 2배로 길어집니다. 체감 속도가 생명인 현재 단계에서는 **XML 프롬프트 리팩토링만으로도 충분한 퀄리티 향상이 가능**합니다.
> 2. **음성 녹음 입력(Voice-to-Blog)**: 별도의 음성 파일 업로드 인프라(Supabase Storage + Whisper API 연동)가 필요하므로, 이후 모바일 앱 고도화(Phase 6) 단계로 미루는 것을 제안합니다.
> 3. **크롬 확장프로그램**: 별도의 코드베이스(Repo)로 프론트엔드를 완전히 새로 개발해야 하므로 현 SaaS 내부 엔진 업데이트와는 별개의 프로젝트입니다.
