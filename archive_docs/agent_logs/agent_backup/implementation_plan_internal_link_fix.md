# 무작위 내부 링크(Internal Link) 삽입 버그 개선 플랜

대표님께서 지적하신 내용은 SEO 블로그 자동화에서 굉장히 흔하게 발생하는 **'강제 내부 링크 주입에 의한 문맥 붕괴(Contextual Mismatch)'** 현상입니다. 

현재 시스템은 SEO 지수를 높이기 위해 무조건 "가장 최근에 작성한 원고 2개"를 가져와 새 글에 억지로 끼워넣도록 지시(Prompt)되어 있습니다. 그렇다 보니 행정사님이 [음주운전 구제] 글을 쓴 직후에 [E-7 비자] 글을 쓰면, AI가 두 개의 전혀 다른 주제를 한 글에 구겨 넣으면서 스팸(Spam) 문서처럼 보이는 대참사가 발생한 것입니다.

이를 해결하기 위한 스마트한 개선 플랜을 제안합니다.

## User Review Required

> [!WARNING]
> 현재의 무조건적인 링크 삽입은 오히려 네이버 봇(C-Rank)에게 어뷰징으로 찍힐 위험이 큽니다. 아래와 같이 AI가 **'문맥적 연관성'** 을 스스로 판단하게끔 로직을 수정하고자 합니다.
> 
> **[개선 방향: 선택적 문맥 링크 주입]**
> 1. DB에서 과거 원고를 2개가 아니라 **5개**를 여유 있게 가져옵니다.
> 2. AI에게 프롬프트로 다음과 같이 엄격하게 지시합니다.
>    *"아래 5개의 과거 글 제목 중, 현재 작성 중인 타겟 키워드와 맥락이 이어지는 글이 있다면 최대 1~2개만 골라서 자연스럽게 삽입해라. 만약 전혀 무관한 주제(예: 비자 vs 음주운전)라면 억지로 링크를 삽입하지 말고 완벽히 무시해라."*
> 3. 결과적으로, E-7 비자 글을 쓸 때는 과거에 쓴 'F-5 영주권 비자' 글이 있다면 자연스럽게 링크가 달리지만, '음주운전 구제' 글은 AI가 똑똑하게 필터링하여 버리게 됩니다.

## Proposed Changes

### [MODIFY] `src/app/api/generate-seo/route.ts`
- 과거 작성 글 조회 쿼리(`findMany`)의 `take: 2`를 `take: 5`로 늘려 후보군을 넓힙니다.
- `internalLinkInjection` 시스템 프롬프트를 전면 수정하여, **강제 삽입**에서 **조건부 선택 삽입(연관성이 있을 때만)** 으로 변경합니다.

## Verification Plan
### Manual Verification
- 로직 수정 후, 서로 전혀 다른 두 개의 키워드(예: "맛집 추천" -> "법인 파산")로 연속해서 글을 생성해 봅니다. 두 번째 글에 첫 번째 글의 링크가 억지로 삽입되지 않는지 눈으로 확인합니다.
