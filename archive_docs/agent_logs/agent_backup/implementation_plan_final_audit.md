# 🎯 전문가 관점 SaaS 최종 런칭 감사(Audit) 및 보완 플랜

프로덕트의 코어 로직(AI 클러스터링, RAG 기반 SEO HTML 생성, 1인칭 스토리텔링, 요금제 모델, UI/UX)은 현재 B2B SaaS 시장에 즉시 내놓아도 손색이 없을 만큼 훌륭하게 설계되어 있습니다.

하지만 **"고객이 이 SaaS를 써서 실제로 돈을 벌게(상위노출하게) 만들어 주느냐?"** 라는 가장 본질적인 관점에서 코드를 감사(Audit)해 본 결과, 정식 런칭 전 반드시 짚고 넘어가야 할 **2가지 치명적 누락 요소**를 발견했습니다.

## 🚨 보완이 필요한 핵심 문제점

### 1. 하드코딩된 제목 (가장 심각한 CTR 하락 요인)
현재 `src/app/dashboard/write/page.tsx` 로직을 보면, 글이 생성될 때 제목이 `강남 행정사 (SEO 최적화)` 처럼 무조건 **키워드 + (SEO 최적화)** 로 하드코딩되어 저장됩니다.
- **문제점:** 네이버 검색 유저들은 제목(Title)이 매력적이지 않으면 절대 클릭하지 않습니다. 본문 내용이 아무리 훌륭해도 제목이 로봇 같으면 트래픽을 얻을 수 없습니다.
- **해결책 (AI 후킹 제목 생성):** 
  AI 프롬프트에 `<title>매혹적인 후킹 제목(1인칭)</title>`을 최상단에 출력하도록 지시합니다. 클라이언트에서 스트리밍 중 이를 실시간으로 파싱(추출)하여, UI의 제목란에 찰떡같은 "어그로성 제목"이 자동으로 꽂히게 만들어야 합니다. 추가로 제목만 따로 복사할 수 있는 **[제목 복사]** 버튼도 필요합니다.

### 2. 키워드 카니발라이제이션 (유사문서 저품질 위험)
- **문제점:** 만약 고객이 "음주운전 구제"라는 키워드가 좋다고 해서, 1주일 동안 똑같은 키워드로 5번 글을 쓴다면 어떻게 될까요? 네이버 알고리즘은 이를 '유사문서 어뷰징'으로 판단해 해당 블로그를 **저품질(나락)** 로 보내버립니다.
- **해결책 (중복 키워드 경고):**
  고객이 글쓰기 버튼을 누를 때, 최근 30일 이내에 이미 작성한 적 있는 키워드라면 *"⚠️ 최근 한 달 내에 이미 작성하신 키워드입니다. 네이버 저품질 위험이 있으니 다른 키워드로 작성하시는 것을 권장합니다."* 라는 경고창(Toast)을 띄워 고객의 블로그를 보호해야 합니다.

## Proposed Changes (수정 계획안)

### [MODIFY] `src/app/api/generate-seo/route.ts`
- 시스템 프롬프트(System Prompt) 최상단에 다음 규칙을 강제합니다:
  `응답의 가장 첫 줄에 반드시 <post_title>네이버 검색 유저의 클릭을 유도하는 매혹적인 1인칭 후킹 제목</post_title> 을 작성해.`

### [MODIFY] `src/app/dashboard/write/page.tsx`
- **제목 파싱 로직 추가:** `completion` (스트리밍 텍스트)가 들어올 때 `<post_title>...</post_title>` 정규식을 돌려 제목을 추출하고 `postTitle` 상태값에 업데이트합니다.
- **본문 분리:** 에디터 미리보기(Preview) 화면에는 `<post_title>` 부분을 날려버리고 순수 HTML 본문만 보여줍니다.
- **제목 복사 버튼:** 생성된 매력적인 제목 옆에 자그마한 `[제목 복사]` 버튼을 달아, 네이버 에디터에 붙여넣기 쉽도록 UX를 개선합니다.

### [NEW/MODIFY] 중복 키워드 방지 로직 (API 연동 여부 결정 필요)
- 사용자가 "바로 글쓰기"를 누르는 순간 DB의 `Article` 테이블을 조회하여 중복 여부를 체크합니다. (해당 기능은 서버 액션 `checkKeywordDuplicate.ts` 생성으로 해결)
