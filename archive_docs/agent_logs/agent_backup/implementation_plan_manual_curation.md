# 수동 키워드 생성 (UX 및 속도 개선) 구현 계획

대표님 말씀대로 초기 접속 속도가 느려진 이유는, 대시보드 페이지에 진입하자마자 AI 서버와 네이버 서버를 동시에 호출하며 키워드를 만들어오기 때문입니다. 이 과정을 **'사용자가 버튼을 눌렀을 때만'** 작동하도록 변경하면 대시보드 진입 속도가 0.1초 컷으로 매우 빨라집니다!

## Proposed Changes

### 1. `src/app/dashboard/DashboardCuration.tsx` (핵심 수정)
- **[MODIFY]**: 기존의 '서버 컴포넌트(자동 실행)' 방식을 '클라이언트 컴포넌트(수동 버튼 실행)' 방식으로 변경합니다.
- 초기 화면에서는 키워드 대신 **[✨ 오늘의 맞춤형 로컬 키워드 발굴하기]** 라는 예쁜 버튼만 나타납니다.
- 버튼을 클릭하면 로딩 스피너(빙글빙글 도는 애니메이션)가 나타나며, 백그라운드에서 AI와 통신을 시작합니다.
- 성공적으로 데이터를 받아오면 3개의 키워드 카드가 짠! 하고 나타나도록 부드러운 UI 상태(State) 관리를 추가합니다.

### 2. `src/app/dashboard/page.tsx`
- **[MODIFY]**: 기존에 자동 생성을 기다리기 위해 씌워두었던 `<Suspense>`(로딩 뼈대) 껍데기를 제거합니다. 이제 버튼을 누르기 전까지는 로딩 대기할 필요가 없기 때문입니다.

## User Review Required
> [!IMPORTANT]
> - 변경 후에는 접속 즉시 키워드가 보이지 않고 버튼을 한 번 눌러야 한다는 점(1-depth 추가)을 고려해 주세요. (대신 첫 화면 로딩 속도는 비약적으로 상승합니다.)
> - 버튼 문구는 "✨ 오늘의 맞춤형 로컬 키워드 발굴하기" 로 디자인할 예정입니다. 변경을 원하시면 피드백에 남겨주세요.

## Verification Plan
1. 코드 수정 후 빌드를 점검합니다.
2. 메인 대시보드 페이지 렌더링 속도가 1초 이내로 빨라졌는지 확인합니다.
3. 버튼을 클릭했을 때 로딩 애니메이션이 나오고 정상적으로 키워드 3개가 노출되는지 테스트합니다.
